# 录音与边录边转

来源可以选择系统音频、麦克风、两者混合或单个 App。单个 App 模式需从当前有窗口的程序中选择进程；包含其子进程以覆盖浏览器的音频进程，开始前检查进程是否已退出或 PID 是否复用。它使用 Windows 的 Process Loopback API，不读取浏览器 Cookie，也不捕获其他 App 的音频。

Windows Process Loopback 的系统要求为 build 20348 及以上，应用最低要求 Windows 11。来源没有播放音频时会得到静音；受保护媒体或不同程序的特殊音频路径可能无法捕获，需逐个程序验证。系统模式跟随开始录制时的默认播放设备，设备热拔插尚需专项验收。

开启「边录边转文字」后，选择已安装的端侧模型和语言。录音开始时固定设置，处理中切换商店模型不影响当前录音。音频每 6 秒生成一个独立、完整的 16 kHz PCM WAV 片段；识别任务位于独立工作进程。ONNX 识别器跨片段保持载入，Whisper 逐片段启动 CLI。GPU / 模型工作与其他 AI 任务使用同一串行门锁，避免并发争抢内存。

「每 6 秒」是音频提交间隔，实际文字延迟还包括推理耗时。模型处理较慢时显示待处理片段数量，不丢弃原始音频。字幕目前按片段范围定位，不提供未结束单词的临时文本或词级强制对齐。

可以切换功能区继续录音。「停止转写，继续录音」只取消推理；已完成字幕保留。「停止并保存」先终止采集、保存音频，再等待剩余字幕完成；可取消剩余转写。出现模型错误时录音继续，录音和已完成的文字保存在本机。中间音频片段用于恢复与排错，目录位于应用数据中的会话与 `recordings` 下。

从媒体库删除内容时，确认框会说明删除范围：字幕、对话、任务历史、会话缓存，以及本应用生成的录音和对应原始采集音轨。外部导入的媒体保留；其他条目仍引用的录音保留。重新关联外部媒体后，仍可按保存的录音归属清理原始录音。清理拒绝链接与越界路径，录音、转写或 AI 尚未停止时不能删除。

## 验证入口

```powershell
# 原生进程内录：仅播放并录制自测进程生成的短测试音，不读取麦克风
./scripts/test-ui.ps1 -Recording
# 持续工作进程：在音频流结束前取得字幕、校验时间偏移并取消等待中的流
./.tools/dotnet/dotnet.exe run --project tests/MemoAI.Tests/MemoAI.Tests.csproj -c Release -- --live
```

此类自测不证明全部 App、音频设备及多小时录音均已验收。麦克风和真实第三方 App 的录制须由用户选择来源后验证；应用不自动操作系统隐私许可。
